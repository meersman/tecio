## [0.4.0]

Python API is now 0-indexed throughout, and `TecplotPltReader` can read legacy
PLT binary files.

### Added

- Read-only support for legacy PLT binary versions v75, v107, and v111 in
  `TecplotPltReader` (and so `tecio.open()`). The version is detected from the
  file's magic string, and the same reader interface is returned for every
  version. Older versions carry less information, so some properties are
  empty: v75 has no variable sharing, passive variables, face connections,
  strand ID or solution time, cell-centered data, or auxiliary data. v75
  pyramids and prisms are stored as bricks with repeated nodes and are
  returned as read. Writers still produce the current format only, and
  `tecio.open()` raises `ValueError` for `'a'` and `'a+'` on a legacy
  file. See the new "Legacy PLT Versions" documentation page for a
  version-by-version comparison.
- `.bbin` and `.bbin8` file extensions are now recognized as Tecplot PLT
  binary files.
- `tecscale` can now transform multiple variables in a single call.
- New `--strand-offset` flag for `tecmerge` to allow multiple transient data
  files to be loaded without automerging overlapping strand IDs (e.g. create
  strand IDs 101, 102, 103, ...).
- First version of a Tecplot data writer plugin for Paraview,
  `TecplotTecioWriter.py`.
- MATLAB function `tecmat2struct` to reformat the zone structures created by
  `tec2mat` into a struct array of zones with arrays accessible by variable
  name.

### Changed

- **Breaking:** the entire Python API is now 0-indexed. Every zone or variable
  index accepted or reported by any Python function, class, or method
  (container indexing, `zone_index`, `var_index`, `get_array`,
  `get_zone_auxdata`, `get_var_auxdata`, shared zone and connectivity indices,
  and so on) is 0-based. The `tecio.libtecio` C wrapper functions keep
  Tecplot's 1-based convention, and the reader and writer classes convert
  automatically. Existing code that passes or compares indices needs to be
  updated, and an index that is off by one often raises no error.
- Passive and shared variables are now specified in the writer methods by
  naming only those variables. Previously a flag was required for every
  variable in the dataset, while data arrays and value locations were only
  given for the active ones. Use `passive_vars=["x", "y", "z"]` and
  `var_sharing={"x": 1, "y": 1, "z": 1}` (variable name or index mapped to the
  shared zone index).
