## [0.2.0]

Consistent variable/connectivity sharing across all three writers and readers, a
unified `precision` option, and per-variable typing for ASCII output.

### Added

- `precision` keyword argument on all writer classes for controlling
  floating-point storage precision (`DataType.FLOAT`/`DataType.DOUBLE`, or
  `"single"`/`"double"` strings). Applies only to floating-point variables,
  integers are always preserved exactly.
  - SZL defaults to `None` (fully automatic, per-variable, unchanged from before).e
  - PLT defaults to `DataType.DOUBLE` and applies to *every* variable,
    including integers — the classic API has no per-variable or integer
    specification capability.
  - DAT defaults to `DataType.FLOAT` (single) and now reads and writes real
    per-variable data types via the `DT=` zone header keyword.
- `ReadZone.shared_connectivity` — 1-based source zone index if a zone's FE
  connectivity is shared, else `None`.
- Internal `WriterMeta`/`ZoneMeta` tracking (`Write.meta`) on all three writers:
  each zone records what was actually written so later zones validate
  `var_sharing`/`con_sharing` against the source zone arrays.

### Changed

- Shared variables and shared FE connectivity now resolve to the source zone's
  actual data automatically on read, on all three formats — `variable.values`
  and `zone.node_map` forward data arrays from the source zone (previously
  returned `None`). Use `variable.shared_zone` / `zone.shared_connectivity` to
  check whether something is shared.

### Fixed

- FE zone writers raised `IndexError` when `node_map` was omitted for a zone
  sharing connectivity via `con_sharing`.
- Shared-variable shape/count validation could miss real mismatches when the
  locally-supplied array was internally self-consistent but disagreed with the
  actual shared source's recorded dimensions.
- DAT: reader parsed every value as `float64` regardless of declared type; now
  defaults to SINGLE (not DOUBLE) when `DT=` is absent, matching the documented
  format default.
- CLI tools previously did not follow shared zone and connectivty to source;
  now sharing is preserved wherever possible and branched if source zones are
  not output

### Removed

- **Breaking:** `dat.Write`'s `sig_digits` parameter — replaced by `precision`.
